# 踩坑记录：GPIO6 (EPD3V3_EN) 实测不控制屏幕供电

## 结论

Waveshare ESP32-S3-Touch-ePaper-1.54 **V2** (ESP32-S3-PICO-1-N8R8) 上，GPIO6 承载 `EPD3V3_EN` 网络（Q2 = AO3401 P 沟道 MOSFET，栅极经 R71 10K 上拉）。

**实测该引脚并不控制屏幕供电**：整个 boot 期间把 GPIO6 恒定拉高、或恒定拉低，屏幕都能正常完成刷新（真实刷新时长约 1273ms，是伪造不出来的）。

## 为什么容易得出错误结论

这块板子上先后得出过「高有效」和「低有效」两个相反的错误结论，问题都出在测量方法，不是板子：

1. **原理图拓扑指向「低有效」**：P 沟道 + 栅极上拉，按常理是低电平导通。
2. **官方 BSP 也指向「低有效」**：`POWER_EPD_ON()` 里写 0。

这两个「看起来很有道理」的推断，与实测不符。

## 测量这类电源门控极性的两个陷阱

1. **不要在同一次 boot 里把 EN 拉到两个电平。** EPD3V3 上有约 10uF 储能电容，控制器靠余电能继续工作 1 秒以上，所以真的断电了也照样能刷完一屏。
2. **不要把 BUSY 当静态电平读来判断是否上电。** BUSY 是控制器输出且板上无上下拉，掉电时浮空、读数随机——用这个方法跑两次会得到完全相反的结果。

## 可靠的测量方法

- 每次 boot 只测一个电平（另一个电平整个 boot 都不驱动）。
- 用 `RTC_NOINIT_ATTR` 存阶段计数器跨 `esp_restart()`；注意 `RTC_DATA_ATTR` 若无初值会落在 `.rtc.bss`，每次启动都被清零。
- BUSY 配置内部下拉，使无响应时稳定读 0。
- 两次测试之间留 10 秒放电。
- 以 `MASTER_ACTIVATE` 之后 **BUSY 高电平的持续时长** 作为判据——真实刷新是 1273ms，伪造不出来。

## 当前代码现状

`main/epd_1in54.c` 仍沿用官方 BSP 的做法配置了该引脚（`epd_gpio_init` 里配置为输出并拉低、`epd_power_off` 里拉高）。因为实测它无影响，留着无害、改动有风险，所以没有去掉。引脚定义见 `main/board.h` 的 `EPD_PIN_PWR_EN`。

相关引脚表见 `README.md` 与 `main/board.h`。
